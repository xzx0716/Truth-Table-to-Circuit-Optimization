# 甲：局部电路搜索的方法、边界与后续路线

本文说明 `src/optimization/local_rewrite.cpp` 的实际实现。正式逐例成绩和运行时间应以绑定最终源码版本的 `results/` 实验记录为准；本文不把单元测试或局部改善当作完整 case 的成绩。

## 1. 输入、目的与输出

输入是已有的一张正确网表，而不是未知函数的猜测。原始真值表已经由 BDD 等构造步骤实现。局部搜索改变网表的连接和门实现，保持每一个输入下的全部输出不变，寻找面积更小或关键路径延迟更低的候选。

搜索函数接收独立种子快照、公共运行预算、搜索参数和候选回调。回调提交完整网表；主程序重新清理无用门、计算实际可达门面积和最大输出到达时间，再决定保留与否。

`area` 是门成本之和；`delay` 是最长信号路径的门延迟之和。它们是电路属性。`runtime` 是完整求解程序从启动到退出的时间，不是某张候选电路的固有属性。

## 2. 已实现的等价变换

实现使用 AND2、OR2、NOT，包含以下通用规则：

- 因式提取：`ab + ac = a(b + c)`，以及 AND/OR 对偶。
- 分配展开：`a(b + c) = ab + ac`，用于探索暂时变大的结构。
- 吸收：`a + ab = a`、`a(a+b)=a`。
- 重结合：改变同类门的括号位置，可能缩短晚到信号的路径。
- 德摩根变换：在直接门和输入/输出反相的实现之间转换。
- 双重取反及构造器已有的常量、幂等和互补化简。

上述规律是对所有布尔输入成立的恒等式，不依赖某个公开 case 的函数类型。实现仍对每次替换执行边界完整真值表检查，防止模板匹配或信号绑定错误。

共享必须在整体上计算。例如旧节点 `ab` 还被别的输出使用时，将 `ab+ac` 改为 `a(b+c)` 并不能删除那一份共享 `ab`。因此局部门数减少不等于最终面积减少。

## 3. 批量代数扫描与单步邻域

直接对每个规则候选重建一次完整网表，成本约与全图大小成正比，大图上非常昂贵。当前先做一次批量代数扫描：

1. 按拓扑顺序处理所有节点。
2. 根据引用数估计此次替换能移除的私有子图。
3. 计算新表达式门面积上界和实际边界到达时间。
4. 对局部面积不增加、到达时间不恶化且有改善的规则，验证等价后在新图中应用。
5. 一次性提交整张重建网表。

这样多个互不冲突的因式提取可以在一轮扫描中共同发生，避免每个因式各重建一次全图。局部估计仅用于筛选；最终是否改善仍以完整网表为准。

随后再执行单步邻域：先在各个区域尝试廉价代数规则，再进入昂贵 cut 搜索。原实现按区域先穷举 cut，可能在第一个复杂区域耗尽预算，覆盖较少；现在将廉价规则优先扩展到更多区域。

## 4. Cut、局部真值表与重综合

Cut 是包围某个根节点的一组边界信号。把边界信号当作独立输入，根节点就成为一个小布尔函数。若边界为 k 个信号，完整检查需要 2^k 行。

实现从根节点出发，逐步将内部信号替换为其输入，枚举不同边界。`max_cut` 是实验可调参数，不是对整个 case 输入位数的限制。边界多一位，真值表通常翻倍；可用时间和内存仍是实际边界。

局部真值表对所有边界组合都成立，即使某些组合在原电路中不可达。这种保守检查保证替换安全，但没有利用不可达组合提供的 don't-care 优化机会。

重综合包括：

- 按边界正序做 Shannon 分解。
- 按逆序分解，并使用另一种 MUX 等价展开。
- 优先考虑晚到边界信号的分解顺序。
- 对两输入函数尝试离线生成的通用模板。

Shannon 分解使用 `f = (~x & f0) | (x & f1)`，对常量分支及相同分支直接化简。模板缓存以局部函数和构造方式为键，保存通用边界编号；使用时重新绑定实际信号。因此缓存不会把别的 case 的答案搬过来，边界实际到达时间也在重建中重新计算。

离线库位于 `include/ttc/generated_templates.hpp`，当前包含 33 张经真值表验证的通用两输入网表，覆盖全部 16 个两输入函数。其中部分来自单位门成本下的精确求解，另加入德摩根等替代结构以应对非对称门成本。**这不是任意门成本、任意到达时间下的完整最优库**，也不能据此声称大电路全局最优。生成过程和验证在 `research/`、`tools/` 中保存。

## 5. 搜索策略的实际区别

生产候选新增 `sweep`：只运行批量代数扫描，按配置轮数反复执行，网表不再变化就停止。每次完整扫描都记录实际成本；只有完整面积和延迟均不恶化时才继续从新图走下一轮。候选仍交给主归档精确选择。该路径避免逐个候选全图重建，可作为低运行成本方案；迭代达到轮数/时间上限不能称为已收敛。

其余四种研究策略仍保留。每种策略都可把找到的完整候选交给主程序；是否继续从该候选探索，由策略决定。

| 策略 | 接受为下一步搜索状态的规则 | 主要作用 |
|---|---|---|
| sweep | 重复完整批量代数扫描至稳定或预算边界 | 提供确定的低开销生产候选 |
| greedy | 选择在当前能量函数下改善的候选 | 较直接地下降 |
| beam | 保留指定束宽内较好的多个候选，允许暂时变差 | 同时探索几条路线 |
| anneal | 依据随轮数下降的温度，随机接受部分变差候选 | 尝试走出局部最优 |
| multistart | 多次从种子出发，改变区域顺序和面积/延迟权重 | 探索不同下降路线 |

内部能量使用归一化面积、加权延迟及超目标延迟项。它只是搜索状态选择的启发式；候选归档使用真实 A/D 支配关系，并不以内部能量替代最终指标。

束宽、轮数、重启数、cut 规模和区域覆盖数均由实验配置决定。配置区域数为零表示不设固定区域数量上限，仍受有限图、轮数及公共预算限制。

每次 multistart 重启有独立访问集合，避免前一次访问记录使后续重启失效；候选输出单独去重。束搜索目前是能量排序束搜索，不是乙任务中的完整 Pareto 动态规划。

## 6. 运行成本估算与预算分配

每次代数扫描、区域处理和候选重建记录工作量、预测耗时及实际耗时。公共预算根据观测更新估计。工作量主要使用网表规模，尚不是涵盖全部图结构特征的精确性能模型。

每个候选可能需要真值表计算、表达式构造、完整网表重建、可达门清理及精确指标计算。区域总耗时观测覆盖这些调用造成的总成本；细分重建记录用于后续启动判断。

昂贵 cut 阶段为当前区域分配由“剩余时间/剩余区域数”和已测重建成本决定的时间份额，避免首个复杂区域吞掉所有预算。时间份额在 cut/构造批次之间检查；一次真值表或递归构造仍可能超过局部份额，但内部继续检查公共总截止。

正 RAM 限制下，读取 Linux 实际 RSS，为输入、核心图、Frontier 和其他模块共同占用的内存留余量。表达式逐个生成并验收，不累计保存所有 cut 表达式。它是提前停止启发式，不能严格证明任何输入都不超过 RAM 上限。

研究模式可以放宽运行时间，测量方法上限；提交模式共用输入预算，并为写出和退出预留时间。拥有合法候选仍必须及时结束程序；先写文件但继续运行至超时并不能确保 case 通过。

## 7. 两层 Pareto 与最终选择

电路层比较 `(area, delay)`，研究归档可以包含超目标延迟的低面积候选。当前主程序通过构造回调收集基础候选，然后接收局部搜索候选。

最终提交策略与研究归档分开：优先考虑达到目标延迟的候选；达标点用交接版归一化折中规则选择；没有达标点时优先最低延迟，再比较面积。该规则不是官方评分公式。

策略层比较完整独立运行的 `(area, delay, runtime)`。生成候选的先后顺序会改变累计发现时间，因此不能把它当作候选自身的第三维。完整策略需串行重复评测，保存计时波动和全部失败。

## 8. 验证与已知局限

单元测试覆盖因式提取、共享、吸收、重结合、常量/直接/互补/重复输出、随机多输出 DAG、四种搜索策略的遍历差异、零轮数、低内存及立即截止。对每张发出的候选独立逐输入模拟全部输出，并检查指标合法性。另已用 ASan/UBSan 检查早期内核；最终版本的正式结果应查回归日志。

两处实际改进已有局部证据：批量扫描能将两处独立因式同时减少；束搜索和多起点确实遍历了贪心不继续访问的区域。它们不自动意味着全部公开 case 的最终输出改善。

局限包括：

- Cut 枚举可能指数增长；配置极大 cut 且不设 RAM 限制时，仍应使用外部研究监督器。
- 完整候选重建和指标验收仍是 O(全图规模)，大图上可能限制有效尝试次数。
- 状态和候选使用哈希去重，未做形式化无碰撞证明。
- 递归表达式和子图访问仍可能受病态深图的栈深影响。
- 没有使用边界不可达组合的 don't-care。
- 运行成本模型与 RSS 停止是启发式；基础构造、归档副本和输出也占资源。
- 没有证明大 case 全局最优，模拟退火也没有有限运行中的全局收敛保证。

## 9. 后续成功扩展与失败备选

若批量扫描有收益，增加多轮扫描、廉价规则组合及共享感知的候选索引；若扫描成本超过收益，依据测得收益和规模减少可选轮数。

若 cut 重写有收益，扩大边界阶梯、缓存规范化、NPN 等价归类和更丰富的通用库；若过慢，优先利用已有缓存、缩小单块但扩大覆盖，或将精确重综合移到离线。

若模拟退火/束搜索发现贪心之外的点，继续扩大步数、束宽和重启并测质量—成本曲线；若不能改善前沿，保留实现为研究配置，默认使用成本更低的方法。

若完整重建成为瓶颈，研究共享感知的增量更新、批量候选验收和局部可删除锥成本；新增量计算必须与完整重算长期对照。

若精确库有效，继续扩大可证明的小问题并按不同门成本/到达时间保留多结构；若在线求解太慢，最终程序仅使用通用库和有限查找，不依赖求解服务。

最后将本模块与乙的多方案映射、跨输出共享、变量顺序和分组构造交替组合；以完整实验判断顺序和力度，避免把单项收益直接相加。
