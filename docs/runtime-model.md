# 运行时间预算、成本估算与两层 Pareto

本文对应甲实现中的 `RuntimeBudget`、主调度和局部搜索。它解释当前代码实际采用的模型，不把预算检查解释成对任意输入和机器都不超时的保证。

## 1. 三种不同的时间

- **电路 delay**：沿门连接传播的到达时间；输入及常数从 0 开始，每个门加上用例规定的门延迟，取全部输出的最大值。
- **solver runtime**：程序启动到退出的墙钟时间，包括读取、构造、搜索、整理、写文件和日志；官方 evaluator 的正确性检查时间不属于 solver runtime。
- **一次优化的额外成本**：例如一轮代数扫描或一次候选重建花费的毫秒数。在线模型预测的是这一项，用于决定是否继续搜索。

候选被发现时的累计 runtime 依赖搜索顺序，不是该电路固有的第三个指标。

## 2. 总截止与局部搜索截止

`RuntimeBudget` 在 `main` 开始时建立，以 `steady_clock` 计时。读完输入后调用 `configure`，但计时起点不会重置，因此已经花在读取上的时间仍然占预算。

正常模式使用输入的 `runtime_limit`；0 或省略表示没有该项课程限制。研究模式显式提供正的 `TTC_RESEARCH_MS` 时，以该值代替课程时间上限。研究结果必须单独标注，不能冒充满足原限制的成绩。

对于正时间上限 \(L\)，初始输出预留为：

\[
R=\max(5\text{ ms},0.1L).
\]

这部分时间留给最终选解、输出和退出，但没有对这些步骤的最坏时间作证明。接口提供 `reserve_for_output`，可以只增大预留；当前默认路径采用上述初值，没有自动测得输出吞吐率后重新校准。

基础电路构造后，主程序还调用 `cap_work`。默认 `TTC_SEARCH_MS=100`，局部搜索最多再使用约 100 ms 的工作窗口。它与课程总截止取较早者，不是每个搜索策略各获得 100 ms。`portfolio` 中的各策略共享此工作窗口。显式研究配置可以扩大这个窗口；非正值不增加局部工作截止，仍受总限制和有限迭代约束。

设已用时间为 \(E\)，工作窗口截止时刻为 \(W\)，则剩余工作时间为：

\[
\operatorname{remaining}
=\max\left(0,\min(L-R-E,\ W-E)\right),
\]

只对存在的截止项取最小值。没有课程限制不等于默认局部搜索无限运行。

默认策略是 `sweep`：进行经过局部等价验证的代数扫描，默认最多 16 轮，遇到结构不变、全局指标变差或预算截止时停止。复杂搜索可通过显式策略和参数研究，默认配置没有宣称覆盖全部可能电路。

## 3. 当前额外成本模型

每种操作分别维护单位成本 \(r_o\)，不同操作不共用一个速率。当前代码的预测为：

\[
\widehat t_o(u)
=\max(0.02\text{ ms},\ 1.5\,r_o\,\max(1,u)).
\]

没有观测记录时，初始速率为 `0.00002 ms/unit`。1.5 是经验余量，0.02 ms 是预测下限。它们不是从课程机器上得到的最坏情况常数。尤其第一次探测可能严重低估，不能将“通过 can_start”理解为操作一定来得及完成。

实际操作耗时为 \(t\)，工作量为 \(u\)，新观测速率是：

\[
r_{\rm obs}=t/\max(1,u).
\]

首次观测直接建立速率；之后更新为：

\[
r_o\leftarrow\max\left(r_{\rm obs},\ 0.75r_o+0.25r_{\rm obs}\right).
\]

因此突然变慢时立即采用较高速率，随后变快时逐步回落。这是偏向少低估的在线启发式，并不是统计置信区间或经过校准的高分位数模型。

`can_start` 要求尚未截止，并且预测成本严格小于剩余时间。计算中仍须周期性调用 `should_stop`，不能只在开始时检查一次。

| 操作记录 | 当前工作量单位 | 记录范围 |
|---|---|---|
| `base` | `p.table.size()`，即真值表输出位字符数 | 读取完成后的基础综合阶段；不包括之前的读取时间 |
| `algebraic-sweep` | 当前门数 + 1 | 一轮代数扫描；不同调用路径是否含候选提交回调存在差异 |
| `rewrite-region` | 当前门数 + 1 | 某个根区域的代数候选处理，可能包含多个替代方案 |
| `cut-region` | 当前门数 + 1 | 某个根的 cut 枚举、重综合及回调开销 |
| `candidate-rebuild` | 当前门数 + 1 | 已完成候选的等价检查、重建、去重和提交回调 |

`base` 的 predicted 值写为 0，只是基础阶段测量，不是一次可用于计算低估率的预测。诊断分析应将它排除。当前 `base` 速率也没有用于在读入前预测整个综合耗时。

这些单位方便首次建模，但还不完整：cut 边界规模、实际候选数量、共享结构、模板复杂度和缓存命中都没有作为独立回归特征。相同门数的两个区域可能成本差别很大。

嵌套记录有重叠：一次 `rewrite-region` 可能包含多次 `candidate-rebuild`，因此不能把各操作累计耗时相加当作总 runtime。等价验证失败、预算中止等提前返回路径也不一定产生候选重建记录，诊断样本不是全部尝试的无偏样本。

## 4. 日志与观测边界

设置 `TTC_COST_LOG` 后，程序在结束时追加记录：输入路径、策略、操作、工作量、预测毫秒、实际毫秒及是否低估。正式性能评测关闭该诊断日志。

每种操作最多保存前 4096 条诊断记录，避免大量日志占用内存；它是**前缀样本**，不是随机抽样。在线速率仍使用每一次 `observe` 更新，超过 4096 条后继续校准，但不再保留明细。

分析误差时，应分别报告冷启动与已有观测、操作类型、样本范围和中止情况。不能用少量探索性日志推断隐藏用例上的稳定误差上界。此前研究计时可能与开发计算并行，只有隔离的正式重复实验适合用于配置间速度比较。

## 5. 内存控制

输入有正 `ram_limit` 时，Linux 的 `should_stop` 从 `/proc/self/statm` 读取当前进程 resident 页数，并按系统页大小换算为 KB。当前 RSS 超过限制的 85% 时，停止追加搜索。这里检查的是 solver 本身，不是 evaluator 或正确性 checker 的内存。

局部搜索还会在某些候选重建前估计新增容器占用。这些检查都不能严格保证峰值内存：分配、扩容、哈希表、临时快照、库分配器开销及一次操作内部的增长，可能发生在两次检查之间。非 Linux 平台没有这段 RSS 检查；官方资源通过与否以 evaluator 为准。

## 6. 当前不能保证的情况

1. 读取真值表、BDD 构造及第一个必要候选不是全部可抢占的。程序需要先得到合法结果，但任意紧限制下，基础构造本身也可能超时或超内存。
2. 基础综合的停止检查主要位于候选之间。一次平衡、映射、回溯或网表整理可能在检查间占用较长时间。
3. 局部扫描、候选复制、`normalize`、`measure`、Frontier 归档及最终选择不是全部可中断。预算只使后续搜索更可控，不是硬实时调度。
4. 1.5 倍余量和 10% 输出预留没有提供数学最坏情况上界。机器负载、WSL 文件系统和缓存状态会影响实际耗时。
5. 默认 100 ms 局部窗口可能在某些输入上停止尚未完成的搜索。未找到改善不等于不存在改善。
6. `TTC_RESEARCH_MS` 不会修改 evaluator 读到的输入限制。研究程序即使内部允许更久，官方评测仍可能按原限制判失败。
7. 正的时间或内存上限是通过条件；target delay 是电路指标目标。不能用电路 delay 小来弥补程序运行超时。

## 7. 两层 Pareto 的作用

电路归档比较实际 area、delay；研究归档可以保留超出目标延迟的点。最终选择仍优先达标，并按交接版相对损失折中规则选出一张电路。这条规则是内部决策，不是官方评分公式。

策略层比较不同完整算法及搜索力度的 `(area, delay, total runtime)`。runtime 来自相同版本、明确配置的完整独立运行；超时、错误或内存失败单独记录，不混入正常前沿。只在所有重复运行通过且 A/D 稳定时，才用单一 A/D 点概括该策略。使用中位数的三目标前沿属于描述性比较，计时范围交叠时不能声称速度差异稳定。

## 8. 后续改进路线

- 为 cut 边界、模板数、缓存命中、候选数量和可删除共享门数增加特征，比较分段模型与保守分位数模型。
- 对冷启动采用独立小批次探测；将预测误差纳入预算余量，而非固定倍率。
- 将候选整理、复制、归档和输出成本显式建模，避免只预测重写主体。
- 为 BDD、平衡、重映射和指标计算增加可恢复的内部检查点。
- 在经完整重算验证后研究增量面积和时序维护，降低候选验收成本。
- 按改善概率和收益／成本调度算子，同时保存被预算拒绝的任务统计，识别模型过度保守造成的漏搜。
- 用不同机器和未参与调参的结构化／随机输入验证误差；单独报告预测能力、资源合规性和电路质量。

这些是下一步方向，不属于当前默认实现已完成的保证。

## 9. 已完成的冷启动校准

第一次公开输入诊断发现代数扫描冷启动明显低估：28次观测中25次低估，实际/预测中位数约10.15。
据此把代数扫描的冷启动单位成本从2e-5改为4e-4 ms/门，其他操作保持2e-5。
第二次同输入诊断为28次中4次低估，实际/预测中位数约0.674，最大约1.755。
这是调参输入上的校准证据，不是独立泛化验证，机器负载也会影响对比。
候选重建等操作仍存在较大尾部误差，详细数据见对应results目录。
首次实验的模型源码应从历史commit恢复；当前预算源码属于校准后模型。
